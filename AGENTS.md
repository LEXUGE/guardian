# Repository instructions

## Writing

- Write contract-first, concise documentation.
- Prefer short sections, exact type signatures, and `A -> B` lifecycle flows.
- State ownership, invariants, and failure behavior directly.
- Use concrete names and standard Rust or Tokio types.
- Avoid history, repeated rationale, speculative abstractions, and prose that
  restates code.
- Write current descriptive contracts rather than roadmaps or future-scope lists.
- Separate generic interfaces from backend-specific details.
- Keep one source of truth per abstraction level and remove superseded files.
